# COTM implementation discipline

These instructions apply to the entire repository.

- Before implementation, identify the stable task ID in `PROJECT_LEDGER.md`. Add an ID there first when the work has none.
- Update `PROJECT_LEDGER.md` in the same change whenever an item materially advances. Preserve abandoned or superseded ideas with an explanation instead of deleting them.
- Cite every task ID advanced by the change in the commit subject or body and in the pull-request description.
- Treat a branch as a reviewable checkpoint. Do not merge to `main` or deploy the public Site until Brenden has tested or explicitly approved the final checkpoint.
- Follow the standing safeguards in `PROJECT_LEDGER.md`, including the permanent prohibition on writing to TWISTER.
